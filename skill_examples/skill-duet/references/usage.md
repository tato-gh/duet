# 短い依頼と返答の扱い

依頼の組み立て方に迷ったときに読む。操作は[SKILL.md](../SKILL.md)を参照する。

entryは同じPJのファイルを読める。参照先と今回してほしいことを渡し、ファイルにない前提だけ補う。同じPJを読めることと、呼び出し側の会話を知っていることは別なので、未記録の合意は省略しない。
以下のパスは例であり、実際の対象に置き換える。雑談なら自然文だけでよい。

## 同じ相手へ差分だけ渡す

```text
前回の指摘を受けて src/cache.ts を更新した。
期限切れの扱いを再確認して。編集は不要。
```

返答を前回の結論に合わせてもらう必要はない。変更後のコードに基づく指摘かを確認する。

## 共有ファイルを読ませる

```text
docs/tasks/cache-expiry.md を読んで実装して。
変更ファイル・検証結果・未解決点を返して。
```

目的と範囲がファイルにあれば再掲しない。不足する条件だけ補う。完了報告は実diffと検証結果に照らし、依頼範囲まで完了したかを確認する。

## 別視点で検討し、判断を引き取る

各entryへ同じ参照先と問いを渡す:

```text
docs/design/cache.md のA案・B案を比較して。
制約に照らして、採用案とその判断が覆る条件を返して。編集は不要。
```

見解が割れたら、判断を分けた前提に絞って戻す:

```text
別の見解では、再起動後もキャッシュを保持する前提でB案を選んでいる。
その前提が仕様にあるか確認して、結論を見直して。
```

一致した人数や断言の強さで決めない。反証は成立条件を確かめる材料であり、そのまま修正要求にしない。伴走中に賛同を得た案でも、採否は目的・制約・根拠から呼び出し側が判断する。
